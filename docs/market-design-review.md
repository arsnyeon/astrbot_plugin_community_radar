# 市场方案调研与后续方向

本轮检索 AstrBot 官方市场缓存，并读取以下项目 README、通过 GitHub API 核对声明许可证。没有复制这些项目的源码；README 描述不代表已验证真实网络可用性。

| 项目 | 可借鉴设计 | 许可与处理 |
|---|---|---|
| [小红书笔记读取器](https://github.com/Akusative/astrbot_plugin_xhs_reader) | 多图真实解码、统一格式、临时用户上下文，单图失败不阻断文本 | AGPL-3.0；只参考设计，不拷贝实现 |
| [小红书冲浪分享](https://github.com/Akusative/astrbot_plugin_xhs_surf) | 阅读模型与人格分享模型分工；不发消息的诊断模式；无值得分享内容就跳过 | AGPL-3.0；只参考设计 |
| [社区精选分享](https://github.com/Wyj425/astrbot_plugin_community_digest) | 公共候选按主题复用，各会话独立订阅、兴趣及发送去重 | MIT；本轮未复制代码，未来复用也需保留版权声明 |
| [B站 AI Bot](https://github.com/chenluQwQ/astrbot_plugin_bilibili_ai_bot) | 观看记忆、主动浏览、消息处理流程，已有版本的设计参考 | AGPL-3.0；不直接移植运行时 |

## 优先级

1. 多图解码与显式证据：当前实现只选择已经取得的缓存画面，不由模型生成图片地址。
2. 平台适配边界：统一内容、媒体类型和能力声明；B站/小黑盒只读搜索先接入。抖音完整浏览仍是专用路径。
3. 未来按会话的订阅与候选池：共享公开内容缓存，不共享私聊提示词或私人兴趣。
4. 不发消息的全链路诊断模式：比在生产群里反复测试更安全。

本轮未安装新插件，未接入小红书或酷安。当前缓存检索未发现明确的酷安条目，不能据此断言市场没有。未来平台访问仍应遵守权限、登录与服务限制。
